# F5/M3 — guided, LOCAL original-source human review

**Editorial utility only — zero automatic approval, zero public seed changes.** This CLI is designed for the human maintainer who personally reads a full original publisher document. It is **not** a source retriever, document authentication service, reviewer impersonation tool, or publication action.

## Why this exists

The first Wagerup approved source-review decision was recorded privately against the then-current **zero-milestone** corpus. Once Wagerup was actually published (October 17, 2026), subsequent M3 packets expose **one already published milestone**. Their source-metadata fingerprint changes when the cutoff, canonical claim, publisher, project or finance input changes, **not merely because the published-milestone count changes**. Reusing the original Wagerup local ledger while adjudicating Narva or Thompson Falls would incorrectly try to nominate an **already published** milestone and mix a historical review with a different release context. Never reset, re-date, revise, overwrite or delete the genuine historical Wagerup decision just to make the next rehearsal pass.

The remedy is **one new private session file for each NEW candidate**, generated from the existing all-pending template without changing any historical receipt. The resulting file still uses the existing canonical seven-row adjudication schema. The target row contains only what the human typed; all others remain pending. Existing `audit:project-execution-adjudications` and `review:f5-release` validators still control source-review eligibility. Later review sessions do not inherit any prior approvals or imply that a reviewer verified their originals.

## How a maintainer runs it

From a checked-out up-to-date SMPT repository:

```sh
npm ci
npm run review:f5-guided -- \
  --id review-m3-2-neo-narva-magnets \
  --proposed-cutoff 2026-10-17
```

The date is a **hypothetical reviewer worksheet cutoff**, not automatically authorized for publication. If the real review takes place on a later date, use the **actual date** for the proposed cutoff or later. Never backdate the reviewer date to fit an earlier cutoff, and never claim the entire site has been reviewed through the hypothetical cutoff.

The CLI first prints the canonical registered issuer source URL, statement, exact pinpoint, publisher publication clock, proposed milestone kind and bounded scope, source cautions and current registry-metadata SHA-256. The reviewer must personally obtain and inspect the **full original source**, then type:

1. An explicit `approved`, `rejected`, or `needs_more_evidence` verdict; their actual name and real review date.
2. Five **independently answered** original-source checks (`y`/`n`); approval requires five actual `y` responses.
3. A genuine explanatory rationale **in their own words** (not an assistant-generated signature).
4. For approval only, an explicit **new** `mil-...` *candidate ID*. No public event is generated by simply entering this ID.
5. The exact 64-character worksheet fingerprint, **manually copied** from the displayed current source-review packet.
6. Final `SAVE` confirmation (private file creation only).

The CLI fails closed on unresolved taxonomy, already-published claims, invalid or future reviewer dates, old fingerprints, unknown source rows, duplicate IDs, mismatched source/project/finance inputs, or incomplete checks. It cannot be run from a CI pipeline or input redirection: a real interactive TTY is required.

On success it creates exactly one new **gitignored, mode-0600** local JSON file:

```text
.project-execution-review/review-m3-2-neo-narva-magnets.adjudications.json
```

It refuses existing session files, symbolic-link private directories, or an unignored path. The historical `.project-execution-review/adjudications.json` containing Wagerup remains untouched, as do every prior per-candidate review file and all tracked research, seed, and release artifacts.

## Continue through the CURRENT, existing read-only release rehearsal

Use the command the tool prints, for example:

```sh
npm run review:f5-release -- \
  --proposed-cutoff 2026-10-17 \
  --file .project-execution-review/review-m3-2-neo-narva-magnets.adjudications.json
```

This is a **hypothetical, offline, private** readiness report only. It must never be interpreted as permission to publish. The source metadata SHA-256 is **not** a checksum of original external document bytes or proof that the site was opened. Never put private rationales, local review ledgers, downloaded original documents or reviewer acknowledgments into GitHub, Vercel, CSV exports, or public website sources.

**On a later canonical corpus revision:** review inputs change, so redo genuine original-source inspection and create a separately named new review session through maintainer-approved revision logic rather than falsifying the old decision. This CLI intentionally refuses overwriting the original file; it is not a re-review history editing tool.

**Publication still separately requires:** an explicit human editorial authorization, valid primary-source pinpoint and claim scope, public reviewer attribution approval, cutoff impact review, a supervised new PR, exact-head data/tests/browser QA and production-deployment verification. `/pathways` and all other taxonomy-blocked claims remain subject to their own separate release authorities.

## Developer regression coverage

`tests/f5-guided-private-review.test.ts` exercises valid synthetic decision construction and hard denial of duplicate Wagerup publication, unresolved taxonomy, stale review SHA, falsified/ambiguous dates, absent or unchecked human attestations, noninteractive scripting and previous signed-ledger overwrite. Synthetic tests do **not** represent real original-source inspections.
