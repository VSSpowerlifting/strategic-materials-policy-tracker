# Preparing the next controls update

1. Run the operator check. Read the primary notice and any earlier notice it amends. Record the actual retrieval date and distinguish signature, publication, first operative day and inclusive last day. After an outage, check intervening official listing pages and record any extra discovery through manual intake. Keep triage decisions in the private journal. [Operator commands](SOURCE_WATCH.md)

2. Verify the previous release against its manifest and retain it. Create a new review overlay pinned to the published baseline. The November example records a continuation of the US-specific suspension and a historical correction to the worldwide graphite legal basis. Use stable instrument, source and measure IDs. Resolve the year as well as the number for each notice. Identify precisely which paragraphs, products and destinations the operative sentence changes. Record references to provisions that survive and unresolved dates. Keep the review state pending and human attestation fields empty. [November overlay](../../../research/controls-review/rc-cn-mofcom-59-2026.json)

3. For a historical coding error, identify the affected measure and the prior status entry by its date and source. Use a reasoned `correct_status` or `remove_status` operation. Retain the prior release for vintage queries. A new legal instrument and a correction to old coding have different evidentiary bases. The source memo should identify which occurred. For any new taxonomy or distribution field, review its rights, meaning and compatibility before adding it to the profile.

4. Build the base and candidate into separate empty directories, twice. Verify the manifests and compare the repeated builds byte for byte. Load both into the independent consumer. Inspect the diff by stable ID, review changed citations, then replay the day before and after every start and inclusive end with a vintage on both sides of publication. Check the unchanged provisions, unrelated instrument family and the number of first-introduced restrictions. Confirm that the old release still yields its old answer. [Build, import and comparison commands](README.md)

5. Route unresolved questions to a named human reviewer. Keep internal commentary and private decisions in the existing candidate workflow. Confirm the signed-versus-issued date basis, the translation of the operative reference, and the exact affected clause IDs against the full original. A candidate build and a completed watch entry establish engineering readiness only. The maintainer records a dated promotion decision separately and decides whether to advance any cutoff, for which cohort, and under what distribution terms. A cohort review provides no basis for advancing the rest of the record. [Candidate review and promotion](../../../data/candidates/README.md)

6. For a subsequent release, update the register when a new official notice enters coverage. Keep new URLs and fingerprints attributable to the reviewed source. Run the repository validation, typecheck, lint, tests and production build, and retain the exact revision, release identities and import receipts for the reviewer. Record private decisions outside the published artifacts. The next update starts from the exact release the maintainer admitted.
